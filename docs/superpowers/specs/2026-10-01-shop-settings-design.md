# Shop Settings (pickup address editable in the admin UI) - Design Spec

Date: 2026-10-01
Status: Approved by the user's message ("trên UI cũng phải có nơi để shop update địa chỉ"). Written spec not separately reviewed; treat as binding.
Extends: `2026-10-01-ghn-shipping-design.md` and `2026-10-01-stats-and-ghtk-design.md`.

## 0. Facts and decisions

- GHN's public API has **no "update shop" endpoint** (only create/list/add-staff), so the shop's pickup location is stored **in our own database** and **sent with every fee request**. Verified against GHN dev on 2026-10-01: sending BOTH `from_district_id` and `from_ward_code` makes GHN price from that origin (Hà Nội -> Quận 1: 53,900 d vs 20,900 d from the shop's registered address) and it works even for a GHN shop that has no registered address; sending only `from_district_id` is ignored by GHN, so district and ward are always sent together.
- Pickup precedence: **settings in the DB** (complete) > env fallbacks (`GHN_FROM_DISTRICT_ID`, `GHTK_PICK_*`) > the carrier shop's registered address (GHN default behavior).
- Editing the settings takes effect immediately for new quotes and checkouts (quote caches are cleared on save). No server restart, no `.env` edit, no API calls by hand.
- `GHN_SHOP_ID` and the tokens stay in `.env` (secrets/infrastructure); the settings page only shows their status read-only.
- Scope: one shop, one pickup address. Out of scope: creating/syncing GHN shops, multiple warehouses, shipment creation.

## 1. Backend

- Entity `ShopSettings` (table `shop_settings`, single row with fixed id `"main"`): `shopName` (<= 100), `phone` (<= 20), pickup `provinceId` (Integer), `districtId` (Integer), `wardCode` (<= 20), `provinceName`, `districtName`, `wardName` (<= 100 each), `address` (street/house number, <= 300), `updatedAt`, `updatedBy` (username). All nullable (no settings yet). `ShopSettingsRepository`.
- `ShopSettingsService`: `get()` (never null: empty settings when no row), `update(request, username)` (admin only, `@PreAuthorize`), `pickup()` returning an immutable `PickupAddress(Integer provinceId, Integer districtId, String wardCode, String provinceName, String districtName, String wardName, String address)` from an in-memory volatile snapshot loaded lazily and refreshed on update (the quote path must not hit the DB per request and must not hold a transaction during carrier HTTP calls). Validation: when GHN is enabled the pickup must be given as ids (`provinceId`, `districtId`, `wardCode`) and is validated + named through `GhnMasterDataService.resolve` (unknown/mismatched ids -> `INVALID_INPUT`; master data unavailable -> `SHIPPING_PROVIDER_UNAVAILABLE`); when GHN is disabled the pickup is given as names (`provinceName`, `wardName`, optional `districtName`) with no ids; shopName required; phone optional but must match the Vietnamese phone pattern when present; address optional. On a successful update clear the quote caches (`ShippingQuoteService.clearCache()`; keep circuit-breaker state out of this: clear only cached quotes) and refresh the snapshot.
- Quote integration: `ShippingQuoteService` takes the pickup from `ShopSettingsService.pickup()`: for GHN include `from_district_id` AND `from_ward_code` in the fee body when the settings are complete (districtId + wardCode); else existing env behavior. For GHTK, `pick_province`/`pick_ward`/`pick_district`/`pick_address` come from the settings names when present, else env; GHTK `isEnabled()` becomes token + client source + (pick province and pick ward from settings OR env). Cache keys include a pickup signature so a changed pickup can never reuse an old quote. `GhnFeeRequest`/`GhnHttpGateway` gain optional `fromDistrictId`/`fromWardCode` (both or none are sent).
- Admin API (`/admin/settings/shop`, ADMIN only, records, `ApiResponse`): `GET` -> `{shopName, phone, pickup: {provinceId, districtId, wardCode, provinceName, districtName, wardName, address}, carriers: {ghn: {enabled, shopId (string or null)}, ghtk: {enabled}}, addressMode ("GHN_IDS"|"TEXT"), updatedAt, updatedBy}`; `PUT` takes `{shopName, phone, pickup: {...}}` and returns the same shape. `shopId` is not a secret (it is shown); tokens are never returned.
- Tests: service validation matrix (GHN ids path incl. mismatched ward/district, GHN disabled names path, missing required fields, phone pattern, admin-only 401/403), snapshot refresh and cache clearing (a quote before/after an update uses the new origin: the FakeGhnGateway records the request body: from ids present only when both set), GHTK pick from settings, GHN disabled + no settings -> table, precedence settings > env, pickup signature in cache key, no DB access or lock held during carrier HTTP (test with a gateway that blocks while another thread updates settings), MockMvc JSON shape tests, restart persistence (settings stored in DB).

## 2. Frontend (admin)

- New admin nav item **Cài đặt cửa hàng** at `/admin/settings` (guarded like the other admin routes). Page: header "Cài đặt cửa hàng"; form sections: **Thông tin cửa hàng** (tên, số điện thoại) and **Địa chỉ lấy hàng** (in `GHN_IDS` mode three dependent selects Tỉnh/Thành -> Quận/Huyện -> Phường/Xã via the existing `useGhnAddress` hook and styled selects, plus the street/house field; in `TEXT` mode a province select (fixed table) + free-text ward/district fields); a status card showing the carriers: GHN (enabled/disabled + Shop ID) and GHTK (enabled/disabled) with plain-language hints ("Thêm GHN_SHOP_ID vào .env để bật GHN"), and a note: "Phí vận chuyển được tính từ địa chỉ này. Thay đổi có hiệu lực ngay cho các đơn mới."; **Lưu** button with loading state, success toast, inline validation (Vietnamese), unsaved-changes indicator and a guard against losing edits (reuse the admin dirty-check pattern), skeleton while loading, error with retry, `role="alert"` for failures, keyboard accessible, responsive. The selects pre-select the saved ids (loading the districts/wards lists for the saved parents) and show saved names even if GHN is temporarily unreachable.
- Pure helpers with unit tests (payload builder per mode, dirty check, validation messages, pre-selection state).
