# GHN (Giao Hàng Nhanh) Shipping Fee - Design Spec

Date: 2026-10-01
Status: Approved by the user's message ("tạm thời anh đăng ký bên GHN dev và đã có lưu trong env"): GHTK's staging registration is broken, so GHN's developer environment is used for now. Written spec not separately reviewed; treat as binding.
Extends: `docs/superpowers/specs/2026-10-01-stats-and-ghtk-design.md` (Part B, GHTK quote service) and the shop spec.

## 0. Decisions and facts

- GHN is added as a **second carrier** next to GHTK. Provider choice is automatic: **GHN** when configured and the request carries GHN ids; else **GHTK** when configured; else the fixed province **table**. Every failure falls back as today (per-carrier circuit breaker, table fallback, `estimated=true`).
- GHN API (from GHN docs/guides, 2026-10-01): dev gateway `https://dev-online-gateway.ghn.vn`, production `https://online-gateway.ghn.vn`. Headers `Token` and `ShopId`. Fee: `POST /shiip/public-api/v2/shipping-order/fee`, body `{service_type_id (2 = standard e-commerce), from_district_id (optional, GHN uses the shop's address when omitted), to_district_id, to_ward_code, weight (grams), length, width, height (cm), insurance_value}`; response `{"code":200,"message":"Success","data":{"total":37000,"service_fee":37000,"insurance_fee":0,...}}` (use `data.total`). Master data: `GET/POST /shiip/public-api/master-data/province`, `/district` (body `{"province_id": n}`), `/ward` (query/body `{"district_id": n}`) returning `province_id/ProvinceName`, `district_id/DistrictName`, `ward_code/WardName` lists. GHN requires numeric ids/codes, not names.
- **Env (the user already has the token in `.env` as `TOKEN_API_GHN`)**: `TOKEN_API_GHN` (token), `GHN_SHOP_ID` (required to enable; the user must create a shop on the GHN dev site and provide its id), `GHN_BASE_URL` (default dev gateway), optional `GHN_FROM_DISTRICT_ID`, `GHN_SERVICE_TYPE_ID` (default 2), `GHN_DEFAULT_LENGTH/WIDTH/HEIGHT` (defaults 25/20/10 cm). GHN is **enabled only when token and shop id are non-blank**. Real calls cannot be verified until the user supplies `GHN_SHOP_ID`; everything is built and tested with mocks and degrades to the table without it.
- Address model: in GHN mode the customer selects **Tỉnh/Thành -> Quận/Huyện -> Phường/Xã** from GHN master data (the 34-unit province table is the fallback only). The server **resolves names from the ids via master data** (never trusts client-sent names) and stores province, district, ward names on the order. In non-GHN mode the current province select + free-text ward remains.
- Scope: fee calculation only (no shipment creation, no tracking).

## 1. Backend

### 1.1 Configuration and gateway
- `ghn/GhnProperties` record (`@ConfigurationProperties(prefix="ghn")`): `token, shopId, baseUrl, fromDistrictId (Integer), serviceTypeId (int, default 2), defaultLength, defaultWidth, defaultHeight`; `isEnabled()`. `application.yaml`: `ghn.token: ${TOKEN_API_GHN:}`, `ghn.shop-id: ${GHN_SHOP_ID:}`, `ghn.base-url: ${GHN_BASE_URL:https://dev-online-gateway.ghn.vn}` etc. Blank config never blocks startup. `.env.example` gets the names.
- `ghn/GhnGateway` interface + `GhnHttpGateway` (RestClient built like the GHTK one with its own timeouts: connect 3 s, read 5 s; wired in a `GhnConfig`; constructor `(props, builder)` so unit tests bind `MockRestServiceServer`): `GhnFeeResult calculateFee(GhnFeeRequest)`, `List<GhnProvince> provinces()`, `List<GhnDistrict> districts(int provinceId)`, `List<GhnWard> wards(int districtId)`. Unexpected/failed/malformed/`code != 200`/negative total -> unchecked `GhnUnavailableException` (never log the token or customer addresses; log class name + HTTP status only).
- `ghn/GhnMasterDataService`: caches provinces (24 h), districts per province and wards per district (24 h, bounded size, Clock-based), resolves ids to names (`resolve(provinceId, districtId, wardCode) -> GhnAddress(provinceName, districtName, wardName)` or empty when any id is unknown/mismatched; district must belong to the province and ward to the district), returns empty lists + marks unavailable when GHN is down (the UI then falls back to text mode). No lock held during HTTP calls.

### 1.2 Quote service
- `ShippingQuoteService` gains GHN: `quote(Cart, QuoteAddress)` where `QuoteAddress(provinceName, wardName, address, Integer provinceId, Integer districtId, String wardCode)`. If GHN enabled and districtId+wardCode present: resolve/validate the ids with `GhnMasterDataService` (unknown ids -> `INVALID_INPUT`... use `ErrorCode.INVALID_INPUT`), compute weight/value as today, call GHN (`insurance_value` = min(value, 5,000,000)), cache 10 min keyed by (districtId, wardCode, weight, valueBucket), own circuit breaker (60 s after a failure, one half-open probe, no lock held during HTTP). Success -> `ShippingQuote(fee=data.total, source=GHN, estimated=false, ...)`. On any GHN failure fall back to GHTK (if enabled and names present) then to the table by province **name** (resolved name from master data when available). Keep GHTK behavior and tests intact.
- `enums/ShippingSource`: add `GHN`.
- `POST /shipping/quote` request gains optional `provinceId`, `districtId`, `wardCode`, `district` (name) beside the existing `province`, `ward`, `address`; `province`/`ward` may be blank in GHN-id mode (the server derives them) — validation: either (province && ward) non-blank or (districtId && wardCode) present.
- `GET /shipping/config` (public): `{provider: "GHN"|"GHTK"|"TABLE", addressMode: "GHN_IDS"|"TEXT"}` (GHN when enabled and master data reachable at the time of the call (cached), else TEXT).
- Public master-data proxy endpoints (GET, public, only meaningful in GHN mode): `/shipping/ghn/provinces`, `/shipping/ghn/districts?provinceId=`, `/shipping/ghn/wards?districtId=` returning `{id|code, name}` lists, `502`-style `ErrorCode.PAYMENT_GATEWAY_ERROR`? No: add `ErrorCode.SHIPPING_PROVIDER_UNAVAILABLE(2019, "Dịch vụ địa chỉ tạm thời không khả dụng", BAD_GATEWAY)`; add them to the public GET list in `SecurityConfig`.

### 1.3 Checkout and orders
- `CheckoutRequest` gains optional `provinceId`, `districtId`, `wardCode`, `district`; `ward`/`province` stay but are no longer required when ids are provided (cross-field validation in the service: GHN ids present OR (province and ward non-blank)); the server stores names resolved from master data when ids are used. `Order` gains `district` (String 100, nullable); `OrderResponse` and the confirmation email show `address, ward, district, province` (null-safe). Everything else in checkout unchanged: the fee is always recomputed server-side from the cart + the resolved address; the client cannot influence it; GHN `deliverable=false`/errors map as for GHTK (`SHIPPING_NOT_AVAILABLE` only when no carrier and no table can serve the address).

### 1.4 Tasks
- **N1 Backend**: everything in section 1 with tests (`MockRestServiceServer` for GHN fee and master data incl. diacritics/JSON shapes and error codes; `FakeGhnGateway` @Primary test double that defaults to "down"; quote matrix GHN ok / GHN down -> GHTK -> table / disabled; id validation (district not in province, ward not in district, unknown ids); cache TTL with the fake clock; breaker per carrier incl. one half-open probe; resolved names stored on the order; checkout with ids and with text; config endpoint modes; master data proxy endpoints, public access; no token/address in logs; full suite green).

## 2. Frontend
- Checkout reads `GET /shipping/config`. In `GHN_IDS` mode the address block becomes three dependent selects (Tỉnh/Thành -> Quận/Huyện -> Phường/Xã) loaded from the proxy endpoints (each select disabled until its parent is chosen, skeleton/loading text, error + retry, reset of children when a parent changes, keyboard accessible, searchable native `<select>` or the existing styled select), plus the street address field; the quote and the order payload send `provinceId`, `districtId`, `wardCode` (and names for display). In `TEXT` mode (or when the master-data calls fail) the current province select + ward text input is used. Quote UI shows source badges "Phí GHN" / "Phí GHTK" / "Phí tạm tính"; everything else as in the GHTK UI. Order detail/admin orders show district and the carrier badge. Pure helpers with unit tests (address-mode decision, dependent select state reducer, payload builder, badge labels).
- Task **N2 Frontend** with Playwright verification using mocked `page.route` endpoints (GHN lists, quotes, failures) and the real backend where possible (MySQL availability permitting).

## 3. Out of scope
GHN shipment creation, tracking, webhooks, COD amount, multiple shops, service selection UI, remote-area surcharge display, GHN production switch (just change `GHN_BASE_URL`/token), migrating the 34-unit table to GHN ids.

## 4. Verification and conventions
